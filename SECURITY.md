# Política de seguridad

## Versiones con soporte

Las correcciones de seguridad se aplicarán a la versión estable más
reciente del proyecto.

Las versiones anteriores no tienen garantizadas actualizaciones de
seguridad. Antes de informar de un problema, comprueba si también afecta
a la versión más reciente.

Si todavía no existe una versión estable publicada, se tomará como
referencia el código de la rama predeterminada del repositorio.

## Cómo informar de una vulnerabilidad

Si descubres una posible vulnerabilidad en mistral-review, comunícala
de forma privada mediante la función de GitHub para informar de
vulnerabilidades:

1. Abre la pestaña "Security" del repositorio.
2. Entra en "Advisories".
3. Pulsa "Report a vulnerability" y completa el formulario.

No publiques vulnerabilidades sin corregir en issues, pull requests
ni otros espacios públicos.

### Información que debe incluir el informe

Siempre que sea posible, indica:

- Una descripción del problema y su posible impacto.
- La versión o el identificador del commit afectado.
- Los pasos necesarios para reproducirlo.
- Una prueba de concepto mínima, si resulta necesaria.
- La configuración o las condiciones necesarias para que ocurra.
- Una posible solución, si la conoces.

No incluyas contraseñas, claves de API, datos personales ni información
confidencial real. Utiliza datos ficticios en los ejemplos.

## Gestión de los informes

Los informes se revisarán según la disponibilidad de las personas
responsables del proyecto. No se garantizan plazos de respuesta ni
de resolución.

Si se confirma una vulnerabilidad, se procurará coordinar su corrección
y divulgación con la persona que la haya comunicado.

Por favor, evita divulgar los detalles técnicos hasta que exista una
corrección o se haya acordado su publicación.
